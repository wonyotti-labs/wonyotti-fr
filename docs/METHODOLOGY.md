# 연구 방법

## 세 가지 별도 질문

1. 원본 내부 계산이 맞는가: 중복·잔액·포지션·비용을 대조한다.
2. 외부 기록과 일치하는가: 원거래소의 거래 ID·시각·가격·수량과 비교해야 한다.
3. 추정 규칙이 다른 시장에서도 유효한가: 비용을 반영한 별도 기간 평가가 필요하다.

1이 맞아도 2와 3은 자동으로 참이 되지 않는다. 봇의 성패만으로 원자료 공개자의 재산을 판단하지 않는다.

## 포지션 복원

체결을 시간순으로 처리한다. 동일 시각에서는 원본 파일과 행의 순서를 사용하며 매수·매도 순서가 불명확한 사건을 품질 보고서에 남긴다. 포지션이 0에서 시작한다고 가정한다. 마지막 미청산 구간은 종료 거래 승률에 넣지 않는다.

XBTUSD의 수량은 USD 계약 수다. BTC 수량이나 레버리지로 해석하지 않는다. 같은 방향 포지션의 계약당 BTC 원가를 가중평균하며 역선물 청산 손익은 다음과 같다.

```text
롱: 청산 계약 수 × (진입 원가 - 청산 원가)
숏: 청산 계약 수 × (청산 원가 - 진입 원가)
원가: 원본 execCost의 절댓값 / 계약 수
순손익: 청산 손익 - execComm - 펀딩 지급액
```

계산은 원본 사토시 금액과 Decimal을 사용한다. 반전 시 수수료를 청산분과 새 진입분에 수량 비례로 나눈다. 펀딩 수량과 복원된 보유 수량을 대조한다. 같은 주문의 부분 체결을 추가 진입 판단으로 반복 계산하지 않는다. 같은 시각에 같은 주문으로 발생한 체결만 합친다.

특수한 0 주문 ID는 모든 거래가 하나의 주문이었다고 보지 않고 체결마다 분리한다. 전체 계약은 원본 정산 통화와 `execCost` 방향으로 역선물·선형·콴토 회계를 구분한다. 선형·콴토 계약은 수량당 원본 정산 비용의 차이를 사용한다. 0 가격의 만기 정산도 별도 처리한다. 현재 상품 사양을 과거 계약에 소급하지 않으며 원본의 정산 통화가 지원 범위를 벗어나면 거부한다.

지갑은 완료 상태만 현금 흐름에 포함한다. 취소 출금, 날짜 역전, 반복 잔액, 과학 표기에 따른 정밀도 저하를 기록한다. 불완전한 시각으로 정확한 일중 잔고·레버리지·계좌 낙폭을 계산하지 않는다.

실현손익 기장일은 이전 날 12:00 UTC부터 해당 날 12:00 UTC 직전까지의 사건과 맞춘다. 마지막 기장일 이후에 발생한 펀딩을 미기장 꼬리로 분리하고 같은 기간끼리 대조한다. 지갑 일별 현금 잔액과 계약별 실현손익은 다른 대조이므로 하나가 맞는다고 나머지 시각 불확실성까지 해결됐다고 하지 않는다.

## 시장 특징과 후보

확정된 15분봉의 과거 수익률, 이동평균 관계, 변동성, 거래량과 매수 체결량 비율을 쓴다. 최초 구간과 결측 이후 256봉은 지표를 사용하지 않는다. 미래 자료를 바꿔도 과거 지표·신호·잔고가 변하지 않는 검사를 둔다.

첫 후보는 다음 봉 종료 시점의 공개 포지션 방향을 정답으로 학습한 표준화 로지스틱 회귀다. 미래 방향은 학습 정답으로만 사용한다. 입력 표준화와 변동성 기준은 학습 기간에서 계산한다. 이 후보는 본인의 진입·추가·청산 판단을 따로 복제하지 않는다. 오래 보유한 구간이 학습 표본을 많이 차지하므로 한계가 크다.

원본 BitMEX 시각의 UTC 연결은 분기별 공식 체결 표본의 ID·가격·수량·시각으로 대조했다. 익명 공개 체결은 계정 소유나 전체 체결을 인증하지 않는다. v1은 바이낸스 특징을 대용 변수로 사용했고, v2는 원본 기간 전체의 공식 BitMEX 5분봉을 특징에 사용한다. BitMEX 봉의 open은 이전 close이므로 실행 가격으로 사용하지 않는다. 별도 거래소의 바이낸스 체결 평가에는 거래소 차이가 남는다.

v2는 다음 5분의 첫 독립 주문 의도를 정답으로 삼는다. 최초 체결 행의 주문 수량과 직전 보유량으로 진입·추가·축소·청산·반전을 구분한다. 미래 최종 체결량·거래 손익을 입력하지 않는다. 같은 주문의 후속 부분 체결은 정답으로 반복하지 않는다. 한 창의 다수 주문과 상태 불일치 창을 보고한다. 주문 제출·수정·취소 시각과 체결되지 않은 주문은 복원하지 못한다.

v2의 특징은 확정한 5분봉의 과거 수익률·추세·변동성·상대 거래량·봉 내 종가 위치와 당시 알려진 포지션 상태다. 최초·결측 이후 288봉은 비운다. 정확히 봉 경계에 발생한 원본 체결은 미래 정답으로 취급하고 직전 포지션 입력에서는 제외한다. 학습 경계를 가로지르는 전체 포지션 에피소드와 마지막 24시간을 제거한다.

## 평가 설계

v4는 최초 노출 확대의 활동과 방향을 따로 학습하며 추가 진입도 방향 표본에 포함한다. 클래스 가중치 없는 선형·비선형 모형을 사용하고, 학습 구간에서만 활동 점수 기준을 산출한다. 실제 봇은 원본의 물타기를 재현하지 않고 정한 노출에서 보유·반전한다.

v5는 같은 노출 확대 표본에서 이후 30·60·120분의 방향별 로그 가격 변화를 회귀한다. 미래 가격은 학습 정답에만 쓰고 정답 끝과 학습 경계를 검증한다. 원본의 실제 체결 가격·리베이트·사후 승패 필터를 넣지 않는다. 예상 가격 변화가 고정 비용 기준을 넘을 때 진입하고 정한 시간까지 보유하되 위험 청산을 우선한다. 실현 가능한 수익 확률이나 체결 모델로 해석하지 않는다.

2026년 9월은 v5의 사전 조건 충족 후 열었고 이후 후보의 미사용 평가가 아니다. 월별 시세가 없었던 실패를 보존한 뒤 같은 기간을 공식 일별 자료로 보완했다. 무거래 결과와 원본·이전 시장 대비 신호 표본 감소도 보고한다.

아래는 v1의 설계다. v2의 고정 후보 수·선택 기준·시간 분리는 [사전 실험 계획](EXPERIMENT_V2.md)을 따른다. 모사 성능은 행동별 지원 표본 수와 함께 보고하고, 빠진 정답 클래스와 표본 부족을 표시한다. 진입 표본이 적은 해의 정확도만으로 일반화하지 않는다.

- 학습: 2020년. 마지막 24시간과 범위 밖 정답을 제외한다.
- 후보 선택: 2021년 BTC. 신뢰도·손절·학습 구간 변동성 한도의 조합 8개를 비교한다. 최소 거래 수와 선택 점수는 평가 전에 코드와 계획 파일로 정한다.
- 평가: 2022~2025년 BTC·ETH·SOL. 선택한 모델과 위험 설정을 고정한다.
- 비교: 위험 제어 제거, 고정 EMA 기준, 동일 초기 자본 비율의 장기 보유, 현금.
- 스트레스: 거래 비용 2배·3배. 연도별 독립 자본 재시작과 30일 블록 재표집은 결과 관찰 후의 후속 진단이다.

평가 데이터를 열어본 뒤 수정한 전략은 새 실험 번호와 관찰 이력을 가진 탐색으로 취급한다. 반응이 좋은 기간만 남기지 않는다. 모델 확률은 금융 수익의 확률이나 보정된 성공 확률이 아니다.

## 체결과 위험

신호는 봉 확정 후 만들어 다음 봉 시가에 실행한다. 선형 USDT 계약의 잔고를 모사하고 편도 수수료·슬리피지·공식 펀딩률을 적용한다. 원자료의 역선물 손익과 단위를 섞지 않는다. 펀딩 기준 가격은 시가를 사용한 근사다.

보유 중 도달한 손절 가격은 슬리피지를 차감하고, 시가가 손절선을 넘었으면 더 불리한 시가로 청산한다. 봉 내부 손절 시각은 관찰할 수 없어 종료 시각으로 기록한다. 실제 대기열·유동성·청산 마크 가격은 구현하지 않았다.

노출 한도는 진입 순간 자본 비율이다. 가격 변화 후 비율은 변할 수 있다. 일중 손실과 누적 낙폭을 다음 관측 시가에서 검사한다. 누적 낙폭 한도는 해당 실행의 영구 중지를 뜻한다. 갭으로 한도가 초과될 수 있다. 최대 낙폭은 봉 종료 잔고와 관측한 순자산 고점으로 계산하여 봉 내부 위험을 모두 표현하지 못한다.

전체 평가 기간의 끝에는 비용을 내고 청산한다. 영속 저널 재생의 중간 중지는 포지션을 보존한다. 매 봉마다 실현손익·활성 거래의 비용·미실현손익의 합과 자산 변화를 대조한다. 추가·부분 청산·반전도 같은 회계를 사용한다. 주문 네트워크 호출은 없다.

SQLite WAL과 전체 동기화 모드로 상태·주문 의도·체결 결과를 하나의 트랜잭션에 기록한다. 동일 사건 재전달은 한 번만 처리하고 값이 다른 중복 사건은 거부한다. 실행 지연 대기열도 상태에 포함한다. 단일 실행과 중단·재개 실행의 전체 결과를 합성 사례와 실제 시세로 대조한다. 해시 연결은 로컬 손상 탐지용이며 악의적인 전체 재작성·끝 삭제까지 독립적으로 인증하는 서명은 아니다.

## 재현 기록

실행마다 새 폴더에 설정, 입력·시장 파일 해시, 코드 해시, Git 상태, Python·의존성 버전을 기록한다. 이후 실행은 코드 스냅샷과 잠금 파일도 보존한다. 초기 실행은 스냅샷 기능 이전이라 코드 해시만 보유한다. 실패·보완·재실행을 삭제하지 않는다.

시장 데이터 최초 수집 폴더와 일별 보완 폴더를 구분한다. 공식 파일이 갱신될 수 있으므로 기존 실행 재현 시 해당 해시의 캐시를 사용한다. `market`을 같은 폴더에서 다른 기간으로 실행하면 정규화 파일과 매니페스트가 갱신될 수 있으므로 다른 수집 범위에는 새 `--output` 경로를 지정한다.

원본과 개인별 파생 출력은 로컬 자료다. 공개 저장소의 테스트·합성 데모와 비공개 원본 기반 연구의 재현 범위를 구분한다.

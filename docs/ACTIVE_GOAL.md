## 이전 작업 기록

2026-10-01 사용자의 요청으로 연속 작업을 시작했다. 첫 모사 후보의 실패 이후 전체 계약 복원·사건별 후보·빈도 조정 후보·다년 평가·장애 복구까지 진행했다. 실거래 연결 전 연구·오프라인 실행의 검증 근거는 [검증 기록](VERIFICATION.md)에 정리했다. 수익성 있는 전략으로 채택한 후보는 없다.

## 수행한 작업 단위

- [x] 원거래소 공식 데이터 경로를 다시 확인하고 체결 ID·가격·시각으로 원본을 대조한다. 실패한 URL 한 개를 전체 자료 부재로 해석하지 않는다.
- [x] 체결 기반 손익과 지갑의 잔차를 시기·원가·반올림·잔여 포지션으로 분해한다.
- [x] 매매 엔진을 순차 처리 상태 기계로 만들고 체크포인트·재시작·중복 입력·중단 후 복구를 검증한다.
- [x] 진입·추가·축소·청산을 구분하는 사건별 학습 자료와 기준 전략을 만든다. 알려진 포트폴리오 상태와 과거 확정 시세만 입력한다.
- [x] 후보 수·선택 기준·이미 관찰한 기간·새 평가 기간을 먼저 기록하고 사건별 후보를 검증한다.
- [x] 원본 보유 기간 중첩을 제거한 시간순 검증, 비용·지연·위험 규칙 제거 실험을 실행한다.
- [x] 넓은 기간과 여러 코인에 같은 고정 후보를 적용한다. 실패한 경우 원인을 남기고 배포 승인으로 취급하지 않는다.
- [x] v2의 잦은 매매 문제를 학습 행동 빈도로 조정하는 v3 가설을 사전 계획에 따라 검증한다. 기존 평가 구간을 미사용으로 재해석하지 않는다.
- [x] 통합 오프라인 실행의 회계·복원·자료 무결성을 검증하고 연구 기록·사용법·커밋을 정리한다.

외부 체결 일치는 공개 자료 일부의 일치 범위만 입증한다. 전체 계정 소유·현재 재산은 봇이나 공개 익명 체결로 인증할 수 없다. 외부 자료 확보가 불가능하면 대체 접근과 실제 실패 증거를 남기면서 독립적으로 가능한 개발을 계속한다.

커밋은 영어 prefix 뒤 한글 명사형 종결을 사용하며 매번 바로 푸시한다. 실제 한 달 시세의 중단·재개 및 급변 시세의 강제 프로세스 종료 후 복구를 검증했다. 실패한 후보·평가·그림과 원자료 한계를 보존했으며 v3의 조건 미충족에 따라 새 2026년 9월 자료는 열지 않았다.

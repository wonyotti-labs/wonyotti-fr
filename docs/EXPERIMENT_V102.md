# 실험 v102 사전 계획: 계약별 체결 기여분의 회계 진단

2026-10-11. [계약 범위 사후 진단](CONTRACT_SCOPE_DIAGNOSIS.md)에서 XBTUSD 체결이 없는 변경 정답의 비율이 학습·진단 사이에 달랐다. 사건 수만으로 각 계약의 기여량이나 봇 손실 원인을 알 수는 없다. 이번 단계는 전체 계좌의 변경 정답을 계약별로 분해하는 회계 진단이다. 새 모형 학습·문턱 조정·매매·후보 채택은 포함하지 않는다.

## 입력과 관찰 범위

공개 구현으로 동일 재현한 v100 보완 가격·전체 분해와 기존 원본 사건을 사용한다. 2020년 학습·2021년 진단은 모두 이미 관찰한 기간이다. 원본 전체 208,596행과 미지원 사유를 유지하고, 지원된 행만 기여량을 계산한다. 원본·가격·모형·기존 실패를 수정하지 않으며 새 시세를 요청하지 않는다. 입력·계획·코드의 해시와 별도 실행 폴더를 기록한다.

사건 범위는 기존과 같은 `[end, label_end)`다. `Trade`와 `Settlement`의 부호 있는 수량·원가를 계약별로 집계한다. 펀딩과 모든 수수료는 v99의 앞선 단계에서 이미 반영됐으므로 체결 원가에 다시 더하지 않는다. 계약을 미래 성과에 따라 선택하거나 창을 삭제하지 않는다.

## 분해식 고정

v99의 수수료 반영 직후, 체결 반영 직전 평가액을 `E0`, BTC 부분 민감도를 `D0`, 비율을 `b0 = D0 / E0`로 둔다. 체결까지 반영한 다음 경계의 평가액은 `E1`, 민감도는 `D1`이다. 단위와 가격·담보 가정은 v96~v100을 그대로 유지한다.

계약 `s`의 창 내 부호 있는 순수량 변화를 `dq_s`, 기록된 부호 있는 체결·정산 원가 합계를 `C_s`로 둔다. 다음 경계의 동일한 가격·계약 승수로 순수량의 평가 항 `M_s`를 계산한다. 역선물은 `-dq_s × 승수 / 가격`, 기존 선형·콴토 계약은 `dq_s × 승수 × 가격`이다.

- 평가액 변화: `dE_s = -C_s + M_s`.
- 민감도 변화: `dD_s = -C_s + M_s`인 경우는 기존 명세의 비역선물·USD 또는 USDT 표시 계약이다. 나머지는 `dD_s = -C_s`다.
- 계약별 기여분: `c_s = (dD_s - b0 × dE_s) / E1`.

`sum(dE_s) = E1 - E0`, `sum(dD_s) = D1 - D0`이므로 `sum(c_s) = D1 / E1 - D0 / E0`이며 기존 `execution_change`와 연결돼야 한다. 모든 계약에 같은 최종 분모를 사용하므로 계약 나열 순서와 무관하다. 이는 선택한 회계 배분식이며 계약을 제거한 실제 계좌나 유일한 인과 기여도가 아니다.

순수량 변화가 0이어도 원가 합계가 0이 아닌 왕복 체결은 보존한다. 순수량이 0인 계약에는 불필요한 가격을 요구하지 않는다. 순수량이 0이 아니면 기존 지원 가격·승수가 필요하며, 임의 가격이나 0으로 대체하지 않는다. 비양수 분모·누락·지원 불일치는 실패 또는 명시적 미지원으로 남긴다.

## 독립 검산과 합성 검사

주 계산은 정수 원가·수량과 60자리 Decimal을 사용한다. 별도 검산은 원본 사건에서 계약별 잔고·수량을 다시 누적하고 유리수 가격 평가로 체결 전후 상태와 각 계약의 변화를 계산한다. 주 계산의 기여분 함수나 반환값을 검산의 정답으로 재사용하지 않는다.

전체 지원 행의 평가액·민감도 변화와 기여분 합계·계약 순서 불변성을 대조한다. Decimal 대조의 허용치는 비교하는 각 값과 절댓값 합계의 최대 크기에 `1e-40`을 곱한 값으로 고정하며 최소 크기는 1이다. 저장된 float64 정답과의 대조는 기존 `1e-10` 절대 오차를 유지하고, Decimal 잔차와 float 오차를 모두 기록한다. 오차가 크면 기준을 넓혀 통과시키지 않는다.

합성 검사는 무사건·펀딩 및 수수료만 있는 창·단독 역선물·비BTC 계약·동시 반대 방향·순수량 0 왕복·정산·서로 상쇄되는 계약·정확한 양쪽 시간 경계·미지원 가격·비양수 평가액을 포함한다. 현재 창 이후 사건을 바꿔도 이전 분해가 같아야 하며, 기존 원본 열과 미지원 행을 그대로 보존해야 한다.

## 출력과 다음 단계의 조건

모든 원본 행과 계약별 원가·수량·평가액·민감도·기여분을 로컬에 보존한다. XBTUSD, BTC 만기 선물, 그 외 계약의 세 집계도 기록한다. 전체와 월별로 다음을 보고한다.

- 지원·미지원 행 수와 계약별 사건 수, 기존 사건 집계와의 일치.
- 각 계약군의 기여분 크기 분포와 기존 합계 정답의 양방향·0 분포.
- XBTUSD 기여분과 기존 합계의 부호 일치·불일치·한쪽만 0인 창 수.
- XBTUSD 사건이 없는 창과 혼합 사건 창의 기여량 및 검산 잔차.

방향 분류는 기존 `1e-12` 경계를 그대로 사용하며 결과에 따라 바꾸지 않는다. 미래 정답 창의 계약군은 진단용으로만 사용한다. 사건이 있는 창만 학습하거나 다른 계약의 손실을 사후 제거하는 정책으로 연결하지 않는다.

회계 검산을 통과하더라도 BTC 전용 정답이나 정책을 자동 채택하지 않는다. 어떤 계약 기여분을 예측할지, 자체 계좌 상태에 어떻게 연결할지, 대조·학습·실행 기준은 후속 계획에서 먼저 고정한다. 기존 v10 수익성 기준과 모든 실패는 유지하며 전체 goal은 계속 진행한다.

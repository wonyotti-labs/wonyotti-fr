# 실험 v114 사전 계획: 관리 점수와 반복 문턱의 요청 억제

2026-10-12. v113에서 기존 v48의 관리 요청은 BTC 2022년 12개, ETH 2023~2025년 64개였다. 원본 학습 범위 밖에서는 모두 보유했으나 양수 BTC의 범위 초과 비중이 손실 ETH보다 높았다. 범위 초과를 바로 청산 규칙으로 쓰지 않고, 고정 점수와 적용 문턱을 직접 대조한다. v38의 첫 추가·축소, v47의 청산 가산 제거와 달리 이번에는 남아 있는 반복 추가·축소의 가산만 구분한다.

## 고정 입력과 비교

- v113의 검산된 전체 원본 학습·보정·진단 세 구간과 봇 두 구간의 실제 관리 입력을 사용한다. 모델·절편·특징·기존 문턱을 다시 학습하거나 선택하지 않는다. 봇의 평탄·대기·위험 차단 시점을 새 관리 판단으로 만들지 않는다.
- 현재 v48과 반복 추가·축소 배율만 1.5에서 1.0으로 바꾼 한 조건을 같은 상태에서 비교한다. 청산과 첫 관리 문턱은 그대로다. 다른 배율·빈도·분위수를 검색하지 않는다.
- 원본 정답은 v35에 봉인된 정답 그대로다. v107의 모든 독립 주문 정답으로 교체하거나 모든 관리 사건을 평가했다고 표시하지 않는다. 기존 v108·v112의 다른 모델 실패도 보존한다.
- 원본 상반기에서 기존 공통·첫 문턱과 선택 지원 수를 재계산해 저장값의 일치를 요구한다. 이 과정은 새 문턱 선택이 아니라 출처 재현이다. 미래 구간은 이 재현에 쓰지 않는다.

## 점수·요청 분해

각 구간과 행동의 전체·첫·반복 상태별 행 수, 원시·보정 점수의 평균·최대·50·90·99·99.9백분위, 기존·직접 문턱 통과 수를 기록한다. 원본은 정답 양성 수·비율 및 요청의 정밀도·재현율·F점수도 계산한다. 청산은 F2, 축소 F1, 추가 F0.5다. 빈 집단은 분모와 지표 부재를 명시한다.

문턱 통과와 최종 요청을 구분한다. 청산→축소→추가 우선순위를 적용한 최종 의도, 우선순위에 밀린 통과 수, 두 조건의 의도 변화 표를 기록한다. 첫 행동의 원시 통과 마스크가 그대로여도 다른 반복 행동의 우선순위 때문에 최종 의도는 달라질 수 있다. 비유한 입력은 원래처럼 보유이며 따로 센다. 기존 봇 의도는 저장된 v113 기록과 모든 행에서 같아야 한다.

후속 자체 계좌 연구에는 원본 하반기의 반복 축소·추가 각각에서 재현율과 해당 F점수가 엄격히 개선되고, 전체 F점수가 악화하지 않아야 한다(허용 오차 1e-12). 청산·첫 행동의 원시 통과 마스크는 보존한다. 반복 집단은 두 행동 모두 양성·음성 20개 이상이어야 한다. 또한 봉인된 봇 두 구간 중 적어도 한 곳의 최종 관리 의도가 실제로 달라져야 한다. 조건 미달 시 새 자체 계좌 후보를 실행하지 않는다. 조건 통과도 수익성 채택이 아니며 다음 매매 계획과 기존 v10의 모든 기준을 요구한다.

## 검산과 한계

숫자 트리의 말단 경로를 별도 방식으로 따라 원시 점수와 절편 보정 값을 전체 행에서 대조한다. 문턱·우선순위·혼동 수·F점수·분위수는 별도 계산과 비교하고 Parquet 저장 후 같은 값을 확인한다. 합성 사례에서 동률 경계, 첫·반복 상태, 겹치는 통과, 비유한 값, 빈 집단과 원시 마스크·최종 의도의 차이를 검사한다. 원본 하반기의 저장된 v35 점수도 재현한다.

이미 관찰한 상태 경로에서의 비교이므로 변경 이후 체결·새 상태·순손익을 알 수 없다. 이번 단계는 재생된 입력에 대한 요청 진단이며 새 매매 수익을 계산하지 않는다. 입력·기존 검산·코드·계획의 지문을 고정하고 새 출력 폴더에 보존한다. 원본·모델·개별 예측의 Git 공개와 실제 거래 연결은 없다.

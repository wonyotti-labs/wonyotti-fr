# 실거래 연결 전 검증 기록

2026-10-01. 검증 범위는 원자료 분석·손익 대조·전략 후보의 반복 연구·상태 복원이 가능한 오프라인 실행이다. 수익성 있는 전략이나 실거래 준비 완료를 입증한 기록은 아니다.

| 요구 사항 | 구현·확인 근거 | 결론의 범위 |
| --- | --- | --- |
| 원본 보존과 Git 제외 | 원본 체결·지갑 파일 해시 재확인, `.gitignore`, 커밋 훅, `check_public_tree.py`, 배포 파일 목록 검사 | 원본·가공 데이터·모델·저널·실험 출력 미포함 |
| 전체 원본 감사 | `audit`, `test_audit.py`, 원본 행 수·중복·종류·시각 순서 보고 | 같은 시각 순서와 초기 포지션은 명시적 가정 |
| 전체 계약 손익·지갑 대조 | `portfolio`, `reconcile_wallet`, 역선물·선형·콴토·만기·정오 기장 경계 테스트 | 동일 기간의 계약 실현손익 대조 완료. 일부 일별 현금 잔액 시각은 불완전 |
| 공식 시장과의 외부 대조 | `verify`, 분기별 공개 익명 체결 ID·수량·가격·UTC 대조 | 표본 일치이며 계정 소유·전체 기록·재산의 인증 아님 |
| 상세 매매·손실 분석 | `study`, `context-study`, `event-diagnose`, 보유·추가 진입·극단 사례·비매매 구간·maker/taker 비용 보고 | 관측과 설명 가설을 분리. 사후 손익을 진입 필터에 사용하지 않음 |

| 반복 연구와 평가 기간 분리 | v1~v5 계획, 후보 목록 선저장, 선택 파일 고정, 개봉 이력, 실패 기록 | 이미 관찰한 기간을 새 최종 평가로 재사용하지 않음 |
| 다년·다시장·위험 규칙 평가 | BTC·ETH·SOL의 고정 평가, 비용 2~3배·추가 지연·위험 제거·기준 전략 비교 | 평가 모델 미채택. 긍정적인 일부 결과만 선택하지 않음 |
| 시간순 재학습·불확실성 | `event-walkforward`, 연도별 자본 초기화, 블록 재표집 | 모사 재학습·독립 재시작·조건부 재표집을 서로 구분 |
| v3 빈도 조정과 개봉 조건 | 학습 구간 빈도만 사용, alpha=0 재현, Brier·로그 손실·신뢰도 구간, 조건 재계산 테스트 | 개발 및 이후 확인 구간이 손실이므로 새 기간 개봉 차단 |

| 9월 공식 자료 보완 | 월별 404·실패 평가 보존, 체크섬 검증 일별 자료, 명시적 범위·원자료 보존 검사 | 자료 보완으로 모형이나 평가 기간 변경 없음 |
| 신호 지원 표본 진단 | 활동·방향·예상 비용 조건의 단계별 통과 수, 실제 거래 수와 구분 | 무거래·낮은 노출에 의한 손실 감소를 예측력으로 해석하지 않음 |
| 분봉 해상도 비교 | 전체 1분 집계와 공식 5분 종가·거래량·거래 수 일치, 같은 주문 연결·날짜 블록 재표집·대수 분해 대조 | 시점 차이가 일부를 설명하며 남은 차이는 실행 가능한 이익의 증명이 아님 |
| 장기 출력 분할 저장 | 묶음 경계별 전체 출력·상태 대조, 실제 다년 실행의 전체 행 일치, 실패 출력·설정·시간 단위 검사 | 출력 버퍼의 크기 제한. 입력·모델 캐시의 전체 메모리 상한 보장은 아님 |
| 부분 매매·회계·중단 복원 | 같은 `TradingEngine`의 메모리 백테스트와 `EventJournal`, 실제 한 달의 전체 결과 대조 | 중간 종료에서 포지션 보존, 전체 종료에서 비용 포함 청산 |

실제 실행의 수치·입력 해시·코드 스냅샷·그림·실패 내역과 검증 파일은 로컬 `artifacts/INDEX.md`에서 확인한다. 공개 저장소의 테스트는 합성 자료만 사용한다. 데이터 보유자가 직접 재현할 명령은 README에 정리했다.

v1~v5 중 채택한 전략은 없다. v4·v5를 같은 오프라인 엔진에 연결하고 실제 시세의 프로세스 강제 종료·재생 복원·회계를 대조했다. 합성 테스트 102개와 정적 검사·원격 CI를 통과했다. v6 전체 시점 비교를 완료했으며 수익성 확보는 별도 미완료 과제로 유지한다. 다음 후보는 [v7 계획](EXPERIMENT_V7.md)의 확정 종가에 따른 진입 대기다.
